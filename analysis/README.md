# Analysis

## Project: All in One – Online Shopping & Multi-Vendor Delivery Ecosystem

## 1. Introduction

The Analysis phase focuses on understanding the problems, requirements, and feasibility of the All in One application. It identifies what the system should do and evaluates whether the proposed project can be developed successfully.

## 2. Purpose of the Analysis

The main purposes of this phase are:

- Identify the problems faced by customers and local vendors.
- Define the functional requirements of the application.
- Identify the non-functional requirements.
- Evaluate the technical and operational feasibility of the project.
- Connect project requirements with development and testing activities.

## 3. Documents Included

| No. | Document | Description |
|---|---|---|
| 1 | requirement-analysis.md | Describes the problem statement, functional requirements, and non-functional requirements. |
| 2 | feasibility-study.md | Evaluates the technical, economic, operational, and schedule feasibility of the project. |
| 3 | requirements-traceability-matrix.md | Connects system requirements with implementation tasks and test cases. |

## 4. Expected Outcome

The Analysis phase provides a clear understanding of the project requirements, feasibility, and development expectations. It serves as a foundation for the system design and implementation phases.

## 5. Conclusion

This phase helps the development team understand what needs to be developed, why it is needed, and how the requirements can be implemented and tested in the All in One application.
